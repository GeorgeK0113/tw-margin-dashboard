## 檔案說明

- `fetch.py` — 從 TWSE(上市)/TPEx(上櫃) 抓取每日融資餘額、收盤價、加權指數 OHLC；
  內建 `_assert_date()`／`_check_stat()` 護欄，端點回應錯天或暫時性失敗都會明確拋例外，不會靜默吞掉
- `compute.py` — 融資成本／維持率遞迴公式、家數統計、均線廣度、官方口徑大盤維持率
- `db.py` / `config.py` — SQLite 資料庫與設定
- `pipeline.py` — 單日「抓取→計算→存檔」流程
- `taiex_ohlc.py` — 補齊加權指數開高低（K 線用，月批次抓取）
- `backfill.py` — 歷史回補，**可重複執行**（已存在的日期會跳過）：
  `python backfill.py 2022-08-01 2026-07-29`
- `daily_update.py` — 每日自動更新進入點（自動補齊漏掉的天數），供工作排程器呼叫
- `dashboard.py` / `template.py` — 產生互動式 `data/dashboard.html`（期間/門檻切換、圖表說明、算法驗證）
- `publish.py` — 把 `data/dashboard.html` 發布到 GitHub Pages（`gh-pages` 分支，每天覆蓋同一個 commit）
- `setup_task_scheduler.ps1` — 註冊 Windows 每日排程（平日 21:45）

## 首次使用

```bash
python -m pip install -r requirements.txt
python backfill.py 2022-08-01 2026-07-29   # 回補歷史（暖機成本基礎，中斷可重跑）
python taiex_ohlc.py                        # 補齊加權指數 K 線資料
python dashboard.py                         # 產生 data/dashboard.html
```

## 已知限制（誠實揭露）

1. **成本基礎暖機期比原站短**：融資成本是用「前一日成本」遞迴推算，暖機期越長、早期
   資料越準。原站從 2014 年開始暖機，本站目前從 2022-08 開始（`config.py` 的
   `WARMUP_START`），只展示 2023-08 之後的資料（`DISPLAY_START`）。這是跌破 130% 家數
   跟原站有落差（544 vs 567）的主因，之後每天自動更新會持續累積，數字會越來越準。
2. **大盤整體維持率採官方公式**：Σ(收盤價×融資餘額) ÷ 上市融資金額餘額，兩者都來自
   TWSE 公開端點，實測可重現官方公布值（誤差 0.01 個百分點）。此為上市口徑，不含上櫃。
3. **個股篩選用代號規則近似**（4碼、排除 00 開頭的 ETF/ETN、排除 91 開頭的 TDR），與
   官方股票清單可能有極少數落差。

## 踩過的坑（給以後維護參考）

開發過程中連續抓到 4 個「回應正常但資料是錯的」的靜默失敗，修法都寫進了 `fetch.py`：

1. TWSE 融資表的欄位名稱重複（融資／融券各一組同名欄位），要保留第一次出現的位置
2. TPEx 舊版價格端點忽略日期參數、永遠回傳最新交易日
3. 自製的加權平均大盤維持率估算值偏離官方值 24 個百分點，改用官方公式
4. TWSE 每日 13:30-13:45 尖峰時段會拒絕 `type=ALL` 查詢，回應仍是合法 JSON，
   必須跟「真的沒有資料」區分開來，否則會被誤判成非交易日而永久漏資料

共同教訓：外部資料要驗證「是不是我要的那一筆」，不能只看「有沒有拿到東西」。
